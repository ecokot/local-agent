## 2. Краткий результат

Добавлены самостоятельный `GitTool`, внутренний Win32 runner, unit-тесты и Windows integration tests. Публичные операции GitTool ограничены восемью read-only операциями: status, branch, head, branches, log, diff, staged_diff и changed_files. Git обнаруживается через `shutil.which("git")`; команды строятся внутри GitTool и запускаются с `cwd=Workspace.root`, без shell. Корень проверяется через `rev-parse --show-toplevel`.

Runner использует CreateProcessW с CREATE_SUSPENDED, Job Object с KILL_ON_JOB_CLOSE, AssignProcessToJobObject до ResumeThread, параллельное чтение stdout/stderr и ограничение сохраняемых данных до 1 MiB на поток. При timeout применяется TerminateJobObject. Код и тесты подготовлены, но не запускались в этой среде. Поэтому работоспособность Win32 runner и прохождение тестов не подтверждены; приёмка не заявляется.

## 6. Технические решения и ограничения

- Таймаут по умолчанию: 15 секунд; максимально допустимый параметр GitTool: 120 секунд.
- Максимум сохраняемого вывода runner: 1 MiB отдельно для stdout и stderr.
- Максимальный лимит log: 100 коммитов; значение по умолчанию: 20.
- Git executable определяется через PATH; пользовательские executable и командные строки не принимаются.
- Git запускается непосредственно на хосте, не через Docker ExecutionBackend.
- Для detached HEAD branch() возвращает None; status сохраняет SHA HEAD.
- changed_files объединяет tracked changes относительно HEAD и untracked файлы, разбирая NUL-разделённые данные.
- В Windows runner stdin перенаправляется на NUL; stdout/stderr читаются отдельными потоками.
- Потенциальные ограничения реализации, требующие проверки: точная семантика porcelain v2 для rename/copy записей; обработка всех ошибок Win32 API; гарантии остановки reader thread; linked worktree; поведение при unborn HEAD. Эти случаи нельзя считать подтверждёнными текущими тестами.
