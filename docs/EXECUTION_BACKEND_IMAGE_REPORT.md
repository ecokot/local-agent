# Отчёт: исправление инструкции сборки ExecutionBackend image

**Объём:** документация и воспроизводимая инструкция.  
**Изменение реализации ExecutionBackend:** не выполнялось.  
**Изменение plan.MD:** не выполнялось.

## 1. Установленная причина

В `src/local_agent/execution/backend.py` Docker запускается с
`--user 10000:10000`. Интеграционный тест
`test_run_tests_tool_executes_pytest_through_docker_backend` проверяет
результат команды `uv run pytest -v`, а также Linux, UID 10000 и GID 10000.

В Dockerfile, ранее приведённом в
`docs/EXECUTION_ISOLATION_RESEARCH.md`, переменная `UV_CACHE_DIR`
не задавалась. Пользователь сообщил о завершении uv до запуска pytest
с ошибкой записи в `/.cache/uv`.

Причина согласуется с конфигурацией Backend и интеграционным тестом.
Настройка `ENV UV_CACHE_DIR=/tmp/uv-cache` направляет кэш в доступный
для записи каталог и не требует изменения кода Backend.

## 2. Нормативная инструкция

Единственным нормативным источником сборки образа
`local-agent-python-test:3.12` назначен
`docs/EXECUTION_BACKEND_IMAGE.md`.

- `docs/EXECUTION_ISOLATION_RESEARCH.md` сохраняет исторические результаты
  исследования и ссылается на актуальную инструкцию сборки.
- `docs/EXECUTION_BACKEND.md` ссылается на нормативную инструкцию.
- README содержит ссылку на неё.
- Dockerfile включает `ENV UV_CACHE_DIR=/tmp/uv-cache`.

## 3. Платформы и результаты

### Историческая проверка разработческого компьютера

Исходное исследование документирует Windows 11 Pro, Docker Desktop
4.99.0, Docker Engine 29.9.3 и Hyper-V backend. В том исследовании WSL 2
не был установлен. Эти результаты относятся только к Hyper-V-конфигурации.

### Домашняя машина пользователя

Пользователь сообщил, что образ был собран на домашней машине с Docker
Desktop и WSL 2. До исправления, по сообщению пользователя, проверки
Python 3.12.15, pytest 9.2.0 и Ruff 0.17.4 прошли, а полный набор тестов
завершился с результатом 1 failed, 537 passed, 3 skipped. Ошибка была
в интеграционном тесте запуска pytest через Docker Backend из-за
недоступного `/.cache/uv`.

Версии Windows, Docker Desktop и Docker Engine для домашней WSL 2
конфигурации в заявке не указаны. Их нельзя достоверно дополнять
предположениями.

### Проверки после документального исправления

На момент подготовки этого отчёта разработчик проверил исходники,
интеграционный тест и соответствие команды запуска. Локальный Docker
Engine разработчику недоступен; новая сборка образа и повторный запуск
теста на домашней машине не выполнялись.

Следовательно, следующие результаты **ожидают подтверждения пользователем
на WSL 2 после пересборки образа**:

- вывод проверки UID/GID и версий инструментов;
- smoke-тест `uv run pytest -v` под UID/GID 10000;
- `test_run_tests_tool_executes_pytest_through_docker_backend`;
- полный `uv run pytest -v`;
- `uv run ruff check .`.

Проверка на Hyper-V после изменения также не выполнялась. Успешный
результат на WSL 2 не будет считаться проверкой Hyper-V и наоборот.

## 4. Изменённые файлы

- `docs/EXECUTION_BACKEND_IMAGE.md` — нормативная инструкция сборки и проверок;
- `docs/EXECUTION_BACKEND_IMAGE_REPORT.md` — этот отчёт;
- `docs/EXECUTION_ISOLATION_RESEARCH.md` — пометка устаревшего Dockerfile и ссылка на нормативную инструкцию;
- `docs/EXECUTION_BACKEND.md` — ссылка на инструкцию подготовки образа;
- `README.md` — ссылка на инструкцию.

Исходники Backend, тесты, `plan.MD` и `MODULE_CONTRACTS.md` не изменялись.

## 5. Вывод

Документальная причина подтверждена по текущему коду и тесту.
Нормативная инструкция теперь задаёт каталог кэша uv в `/tmp` и
содержит команды сборки, проверки пользователя, smoke-тестирования и
интеграционной проверки.

Исправление считается документально подготовленным. Фактическое
подтверждение на WSL 2 требует повторной сборки и выполнения команд
из `docs/EXECUTION_BACKEND_IMAGE.md`. До получения этих результатов
нельзя заявлять, что критерии runtime-приёмки уже пройдены.
